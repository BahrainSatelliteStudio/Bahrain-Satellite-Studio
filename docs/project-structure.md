# تنظيم Bahrain Satellite Studio

## المسؤوليات

| الموقع | المسؤولية |
|---|---|
| `src/routes/` | عناوين الصفحات ووصفها وتحميلها، والتحقق الحالي من دخول الإدارة والزبون. |
| `src/features/tenant-management/` | أقسام إدارة الزبون، الحفظ والسجل والرفع المشترك، الإنشاء وفحص الهوست. |
| `src/features/player/` | تجميع التطبيق، الدخول، الإعدادات، التصفح، الإعلان، التنقل والتسجيل للإشعارات وواجهات قراءة البث. |
| `src/features/activation/` | إدارة الأكواد وتفعيلها؛ لا تغيير في البروتوكول أو معاملات الاسترداد. |
| `src/features/builds/` | حالة GitHub وإعداد التوقيع وطلب البناء مع التحقق الإداري الحالي. |
| `src/features/application-library/` | استعلام مكتبة التطبيقات وتطبيق القالب مع حفظ الأقسام. |
| `src/features/homepage/` | العرض المشترك للرئيسية ومعاينة المسؤول. |
| `src/components/ui/` | أدوات العرض العامة الحالية. |
| `src/lib/player/` | قواعد هوية المحتوى وعزل المعاينة وتفضيلات المستخدم وتشخيص النقل. |
| `src/lib/*.server.ts` | مساعدات الخادم؛ تُحمّل داخل المعالجات ولا تُستورد مباشرة في العرض. |
| `selfhost/panel/` | لوحة مستقلة دون اعتماديات، لا تستورد ملفات TS من المنصة. |
| `drizzle/migrations/` | تاريخ الجداول والسياسات الحالي، دون إعادة كتابة أو إعادة ترتيب. |

## نقاط الدخول الثابتة
الملفات القديمة `src/components/player/PlayerApp.tsx` و`src/components/HomepageView.tsx` و`src/components/ActivationCodesPanel.tsx` و`src/lib/iptv.functions.ts` و`src/lib/activation-codes.functions.ts` و`src/lib/application-library.ts` تعيد تصدير التنفيذ الجديد. بذلك لا تحتاج الشاشات والاختبارات إلى تغيير استيراداتها الحالية دفعة واحدة.

يبقى المشغل الفعلي وواجهات التجربة الجديدة في `src/components/player/`. لا نغيّر منطق الفيديو لمجرد توحيد أسماء المجلدات.

## عناوين الصفحات المحفوظة
الرئيسية `/`؛ الدخول `/auth`؛ الإدارة `/dashboard`؛ إدارة الزبون `/t/$tenantId`؛ المكتبة `/applications`؛ التشخيص `/diagnose`؛ Firebase `/firebase`؛ الرئيسية الإدارية `/site-settings`؛ التطبيق `/p/$slug`؛ المعاينة `/preview/$slug`؛ التثبيت `/install/$slug`؛ الدليل `/guide/$slug`.

واجهات `/api/public/` بقيت في مكانها وبنفس العقود. ملف `src/routeTree.gen.ts` مولّد تلقائيًا، وليس موضع تعديل يدوي.

## عقود لا تتغير أثناء التنظيم
- `TenantConfig` هو عقد العرض المشترك؛ الخادم قد يعيد حقولًا إضافية مثل معلومات الربط والتفعيل.
- `resolveLayout` و`TEMPLATES` يظلان مرجع القوالب والأقسام؛ لا استبدال كامل للإعدادات عند تغيير القالب.
- `progressNamespace` و`progressKey` و`previewChannel` تظل مراجع العزل والهوية والمزامنة؛ لا إعادة تسمية لمفاتيح التخزين القديمة.
- أسماء حقول النسخ الاحتياطية ومفاتيح الاستعلامات وعمليات الحفظ لم تتغير.
- لم يُعدّل شكل `/api/public/config` في اللوحة المستقلة.
- جميع مساعدات الخادم المنقولة تستخدم تحميلًا محليًا للمعالج؛ لا نقل الأسرار إلى ملفات المتصفح.

## أسلوب التغيير القادم
ابدأ بقسم واحد واختبره، ثم انتقل للقسم التالي. لا تخلط تغيير الصلاحيات أو أسعار الباقات أو حدود الاستخدام أو التوقيع مع نقل الملفات. لا تُنشئ مجلدات فارغة لمجرد استكمال الشكل، ولا تفكك ملفات أدوات العرض العامة أو الملفات المولّدة بسبب عدد أسطرها.
